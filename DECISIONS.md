# DECISIONS

Append-only. One line each, newest at the bottom. If you reverse a decision, add a new row — don't edit the old one.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-09-04 | **No database.** In-memory `World` built from the 12 JSON files. | Dataset is < 700 KB (150 crew, 147 flights, 39 pairings). Postgres/Neo4j/Mongo/Celery cost the better part of a day and buy nothing at this scale. |
| 2 | 2026-09-04 | **The LLM never calculates.** Every number comes from a deterministic tool; a verifier gate rejects untraced claims. | A controller cannot act on a number that might have been invented. This is the trust boundary the whole architecture is built around. |
| 3 | 2026-09-04 | **Freeze `docs/API_CONTRACT.md` before implementation.** Fixtures derived from the answer keys. | Lets four people build in parallel. Because the fixtures *are* the correct answers, the mock→real swap is a no-op. |
| 4 | 2026-09-04 | **Typed answer object per tier; prose rendered from it.** | Answer keys are structured JSON, so the harness can score us exactly. Prose-first would make that impossible. |
| 5 | 2026-09-04 | **JUDGE's default config must reproduce the answer keys exactly.** Policy sliders layer on top. | Ranking is cost-deterministic `(legal, cost_inr, delay_hours)` off a fixed rate card. This is correctness, not preference. |
| 6 | 2026-09-04 | **`JOINT` is a first-class module, enforcing disjointness.** | S6 is a joint optimisation (`total_cost_inr: 42500`). Without a disjointness constraint you assign C-3305 to both aircraft — an infeasible ₹37,000 plan. |
| 7 | 2026-09-04 | **Describe JUDGE as *provably optimal*, not *learned*.** Log preference pairs for future learning. | We don't have a trained ranker and shouldn't claim one. The exact-optimality claim is stronger and survives questioning. |
| 8 | 2026-09-04 | **Held-out scenarios (`internal/`) are locked.** Run once at T+21 as an honest self-check. | Tuning against the judging set is overfitting. A defensible 96% beats an unexplainable 100%. |
| 9 | 2026-09-04 | **Out of scope: passenger rebooking, disruption-risk prediction.** | Pax impact is a RIPPLE *output*, not a subsystem. The dataset README is explicit that risk scores are provided input — teams do not build prediction. |
| 10 | 2026-09-04 | **`Option` keeps answer-key field names verbatim.** Additive fields only. | The harness compares against them directly. Renaming breaks scoring silently. |
| 11 | 2026-09-04 | **Correction to #6: greedy does *not* fail S6.** The trap is double-booking, not suboptimality. | Sequential greedy that removes the assigned crew reaches ₹42,500, because the cost structure is flat (one ₹18,500 reserve, then a plateau of ten captains at ₹24,000). We still build proper assignment (Hungarian, ~10 lines) for robustness — the held-out scenarios may not be flat. Stated honestly so nobody repeats the wrong claim to a judge. |
| 12 | 2026-09-04 | **S6/Q32 is scored on cost + feasibility, never on `crew_id`.** | 20 assignments are equally optimal (2 roles × 10 captains at ₹24,000). dCortex: *"Equal-cost mirror assignments … are equally correct."* Identity comparison would fail 19 of 20 correct answers. Assert `total_cost_inr == 42500`, both legal, IDs distinct. |
| 13 | 2026-09-04 | **Single agent with tools — not a multi-agent system.** Router (Haiku) → Advisor (Sonnet, one tool loop) → deterministic Verifier → Explainer. | All hard reasoning is deterministic Python. Multi-agent would have LLMs conferring about work `core/` already computes exactly, paying serial round-trips for zero correctness on a latency-critical desk. Named honestly as a *pipeline*, not "multi-agent". |
| 14 | 2026-09-04 | **pgvector on the audit-log Postgres.** No dedicated vector database. | Postgres is already required for the audit log and preference pairs. One extension, zero new services, and embeddings can be joined against the decision log in one query. Corpus is ~45 vectors; NumPy is the fallback if Postgres ever leaves the design. |
| 15 | 2026-09-04 | **Retrieval: regex for entities, dense for intent. No BM25, no reranker.** | Full corpus is 776 tokens — router exemplars go in the *cached system prompt*, so it sees all 38 rather than a top-3 approximation. BM25 approximates exact matching we can do precisely with regex, and is near-useless where all 38 docs share one vocabulary. A cross-encoder over 38 candidates costs more than the retrieval it corrects. If two rankers are ever fused, use RRF — raw BM25 and cosine scores are not on a common scale. |
| 16 | 2026-09-04 | **Mask IDs before embedding**; abstain below ~0.5 similarity. | `"Captain C-1042 calls in sick"` → `"Captain <CREW> calls in sick"` collapses Q17 and S1 onto one template — the biggest accuracy win for intent classification. A bad exemplar is worse than none; it steers the planner confidently into the wrong toolchain. |
| 17 | 2026-09-05 | **`core/` rules engine built and scored against dCortex's answer keys.** | S1 7/7, S2 6/6, S6 13/13 both aircraft and ₹42,500 with 20 ties, Q18 verbatim. Written as a starting point for Kashifa's issues #3-#12, with the five data traps documented in the code. |
| 18 | 2026-09-05 | **`claude-opus-5` is the default model; prompt caching on.** | 5/5 tool calls, ~2s, and ~80% of input tokens served from cache — which is what makes a multi-call tool loop affordable. Groq and Ollama remain behind the same protocol. |
| 19 | 2026-09-05 | **The verifier accepts numbers derived from evidence, labelled with the derivation.** | Rejecting "₹5,500 more" (24,000 − 18,500, both sourced) discarded a correct answer. A false positive costs as much as a false negative — it throws away good work and teaches people to ignore the gate. Pairs only, no chaining. |
| 20 | 2026-09-05 | **A clarifying question ends the turn.** | Asked which of three dates a controller meant, the model answered on their behalf and narrated whichever it preferred — the same question gave different answers on different runs. Choosing among them is the desk's call. |
| 21 | 2026-09-05 | **Nothing fails silently.** An empty answer is a bug. | "No data was returned" is indistinguishable from "nothing is wrong". Where no tool ran, the system says what it understood and what is missing. |
| 22 | 2026-09-05 | **Suggest, never substitute.** Near-match ids and wrong ranks are queried, not corrected. | C-1042 and C-1024 differ by one transposed digit and one of them is nobody. Auto-correcting would dispatch a different human being to an aircraft. |
| 23 | 2026-09-05 | **Conversation state lives in `agent/conversation.py`; `Advisor` stays stateless.** | A controller interrogates a recommendation rather than reading it. Most follow-ups are answerable from the previous turn's data, so "why not X" costs no tool call. Keeping the advisor stateless leaves it testable one question at a time. |
| 24 | 2026-09-05 | **Filters take ranges, and an unknown operator is rejected rather than ignored.** | Q04 is an interval — its key says `valid_to between 2026-09-15 and 2026-10-15`. Equality-only filters meant answering it would have required handing the model 600 rows to pick six from, putting the selection back above the trust boundary. A silently dropped bound widens a compliance list with nothing to notice it by. |
| 25 | 2026-09-05 | **Drafting the crew notification is the model's job; every time in it is the roster's.** | Q36 is a scored tier-3 question and the one task where prose is the deliverable. `notification_brief` reads the report times, stations, legs and overnight from the roster and derives the acknowledgement deadline from the crew member's own reachability; the model may reword the message and may not move a time. No phone number is ever written — the dataset has none, and a plausible-looking one is exactly the invention this system exists to prevent. |
| 26 | 2026-09-05 | **Tier-1 results render as an aligned table, and the row limit is 25.** | Ten truncated Q01, whose key lists all twelve BLR reserves — a correct answer cut into an incomplete one. `key=value` repeated the column name on every row and moved the values in every line. A column identical across every row is stated once above the table rather than repeated, never dropped. |
| 27 | 2026-09-05 | **Crew records carry the person, not only the id.** Name, seniority, base and reachability ride on every option. | "Assign Captain C-3310" is not what a controller says at 05:00; they phone D. Reddy. The id stays alongside it because the id is what goes into the roster system and two people can share a surname. |
| 28 | 2026-09-05 | **Seniority is reported, never sorted on.** | The dataset gives years of service but says nothing about how the desk breaks a tie, and real carriers differ — some protect senior days off, some rotate. Choosing a direction silently would decide which human gets called at 05:00 on a convention nobody stated. The tie is surfaced instead (`equal_cost_alternatives`) and the desk breaks it. |
| 29 | 2026-09-05 | **`disruption_risk_score` rides beside an option and never enters the ranking.** | dCortex provides these pre-computed and is explicit that teams do not model them — "treat them like a weather forecast; your job is what the controller does about it". A risk score is not a rule, and letting one reorder legal options would be the prediction we were told not to build. A test asserts the sort key never mentions it. |
| 30 | 2026-09-05 | **Every entity a seed call needs is exposed identically by both ports.** | Postgres normalises pairing crew and days into tables; the JSON nests them. A seed must not have to know which backend is live, so the placeholder flattens and Postgres joins the crew identity onto reserve rows. |
| 31 | 2026-09-05 | **A data lookup is answered in prose, with its tables kept underneath as evidence.** | Tier 1 was never polished — right when a lookup meant one small table and the model was llama3.1:8b. "Who is C-1042" now fans out to nine calls across seven entities, and the template answered it with "16 records." and seven tables: every fact present, the question unanswered. The ban is replaced by four narrower defences — lookup-specific instructions that forbid recommending or inferring a situation, the tables kept below the prose, no polish when there are no rows, and no polish for EXPLAIN_RULE, which is the shape that produced the original fabrication. |
| 32 | 2026-09-05 | **A time of day is one fact however it is spelled.** | The gate was rejecting `06:00Z` against a stored `2026-09-15T06:00:00+00:00` and discarding the whole answer. Three faults behind it: `\b` cannot match `T06:00`, so the pattern found the `00:00` of the UTC offset instead — which also meant every timestamp silently vouched for a midnight nobody had said; and Postgres `datetime` objects were skipped entirely, so a report time could be in the trace, printed in the table, and still not be evidence. |
| 33 | 2026-09-05 | **A crew member is written `Rank Name (C-XXXX)` everywhere — one helper, `explainer.who`.** | A controller phones a person; the roster system takes an id; and two people can share a surname, so neither half is droppable. The rule binds the templates, the conversation follow-ups and the model instructions alike, and falls back to the bare id when no name is loaded rather than inventing one. |
| 34 | 2026-09-05 | **Clock normalisation is narrow on purpose: zero seconds only, UTC only.** | This is the one place the gate calls two strings the same fact, so a loose equivalence is a hole in it. `06:00:30` is not `06:00`, and `06:00+05:30` is a different instant from `06:00Z`. Every timestamp in this dataset ends `:00` and is UTC, but the check does not depend on that staying true. |
| 35 | 2026-09-05 | **A controller may name a person in words, and an ambiguous name is asked about, never guessed.** | The system writes "Captain A. Nair (C-1042)", so a controller writes "Nair" back — and every surname in this dataset is shared. "Nair" is seven people and "A. Nair" is two of them, a Captain and a Cabin Crew member at the same base. Context narrows first, then a stated rank or base; what remains is a question. This is #22 applied to names. |
| 36 | 2026-09-05 | **An unfiltered listing is never an answer.** No crew lookup is seeded without something to narrow by. | Asked "is Nair available?" the system had answered with all 150 crew. A table nobody asked for is worse than the empty answer #21 forbids: it looks like a reply, so it is not obviously wrong, and the controller has to notice for themselves that their question went unanswered. |
