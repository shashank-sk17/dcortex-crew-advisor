| # | Date | Decision | Why |

| 1 | 2026-09-04 | **No database.** In-memory `World` built from the 12 JSON files. | Dataset is < 700 KB (150 crew, 147 flights, 39 pairings). Postgres/Neo4j/Mongo/Celery cost the better part of a day and buy nothing at this scale. |
| 2 | 2026-09-04 | **The LLM never calculates.** Every number comes from a deterministic tool; a verifier gate rejects untraced claims. | A controller cannot act on a number that might have been invented. This is the trust boundary the whole architecture is built around. |
| 3 | 2026-09-04 | **Freeze `docs/API_CONTRACT.md` before implementation.** Fixtures derived from the answer keys. | Lets four people build in parallel. Because the fixtures *are* the correct answers, the mock→real swap is a no-op. |
| 4 | 2026-09-04 | **Typed answer object per tier; prose rendered from it.** | Answer keys are structured JSON, so the harness can score us exactly. Prose-first would make that impossible. |
| 5 | 2026-09-04 | **JUDGE's default config must reproduce the answer keys exactly.** Policy sliders layer on top. | Ranking is cost-deterministic `(legal, cost_inr, delay_hours)` off a fixed rate card. This is correctness, not preference. |
| 6 | 2026-09-04 | **`JOINT` is a first-class module, enforcing disjointness.** | S6 is a joint optimisation (`total_cost_inr: 42500`). Without a disjointness constraint you assign C-3305 to both aircraft — an infeasible ₹37,000 plan. |
| 7 | 2026-09-04 | **Describe JUDGE as *provably optimal*, not *learned*.** Log preference pairs for future learning. | We don't have a trained ranker and shouldn't claim one. The exact-optimality claim is stronger and survives questioning. |
| 8 | 2026-09-04 | **Held-out scenarios (`internal/`) are locked.** Run once at T+21 as an honest self-check. | Tuning against the judging set is overfitting. A defensible 96% beats an unexplainable 100%. |
| 9 | 2026-09-04 | **Out of scope: passenger rebooking, disruption-risk prediction.** | Pax impact is a RIPPLE *output*, not a subsystem. The dataset README is explicit that risk scores are provided input — teams do not build prediction. |
| 10 | 2026-09-04 | **`Option` keeps answer-key field names verbatim.** Additive fields only. | The harness compares against them directly. Renaming breaks scoring silently. |
| 11 | 2026-09-04 | **Correction to #6: greedy does *not* fail S6.** The trap is double-booking, not suboptimality. | Sequential greedy that removes the assigned crew reaches ₹42,500, because the cost structure is flat (one ₹18,500 reserve, then a plateau of ten captains at ₹24,000). We still build proper assignment (Hungarian, ~10 lines) for robustness — the held-out scenarios may not be flat. Stated honestly so nobody repeats the wrong claim to a judge. |
| 12 | 2026-09-04 | **S6/Q32 is scored on cost + feasibility, never on `crew_id`.** | 20 assignments are equally optimal (2 roles × 10 captains at ₹24,000). dCortex: *"Equal-cost mirror assignments … are equally correct."* Identity comparison would fail 19 of 20 correct answers. Assert `total_cost_inr == 42500`, both legal, IDs distinct. |
| 13 | 2026-09-04 | **Single agent with tools — not a multi-agent system.** Router (Haiku) → Advisor (Sonnet, one tool loop) → deterministic Verifier → Explainer. | All hard reasoning is deterministic Python. Multi-agent would have LLMs conferring about work `core/` already computes exactly, paying serial round-trips for zero correctness on a latency-critical desk. Named honestly as a *pipeline*, not "multi-agent". |
| 14 | 2026-09-04 | **pgvector on the audit-log Postgres.** No dedicated vector database. | Postgres is already required for the audit log and preference pairs. One extension, zero new services, and embeddings can be joined against the decision log in one query. Corpus is ~45 vectors; NumPy is the fallback if Postgres ever leaves the design. |
| 15 | 2026-09-04 | **Retrieval: regex for entities, dense for intent. No BM25, no reranker.** | Full corpus is 776 tokens — router exemplars go in the *cached system prompt*, so it sees all 38 rather than a top-3 approximation. BM25 approximates exact matching we can do precisely with regex, and is near-useless where all 38 docs share one vocabulary. A cross-encoder over 38 candidates costs more than the retrieval it corrects. If two rankers are ever fused, use RRF — raw BM25 and cosine scores are not on a common scale. |
| 16 | 2026-09-04 | **Mask IDs before embedding**; abstain below ~0.5 similarity. | `"Captain C-1042 calls in sick"` → `"Captain <CREW> calls in sick"` collapses Q17 and S1 onto one template — the biggest accuracy win for intent classification. A bad exemplar is worse than none; it steers the planner confidently into the wrong toolchain. |
| 11 | 2026-09-04 | **Contract reconciled with the pre-built Angular starter** (`docs/CONTRACT_RECONCILIATION.md`). Transport is `POST /api/v1/ask` + `fetch`-streamed SSE; three additive events adopted from the starter — `status`, `rule_check`, `abstain`; `done` gains `grounded`. **PROPOSAL — Shashank to ratify.** | Two contracts existed pre-clock. The repo's rich answer object (answer-key field names) wins; the starter's `abstain` event + pure reducer + demo-safety mock are kept. Additive only — no breaking change for L2/L3. |
| 12 | 2026-09-04 | **Frontend adopts the pre-built `crew-ops-advisor-ui` starter into `frontend/`.** Angular 19 standalone + signals, SCSS, no UI lib. | ~90% of Kiran's Phase-0 deliverable already existed. Rebuilt only the contract model + service for the reconciled transport; added the evidence-rail components (funnel, 7-rule trace, blast radius, policy sliders). |
| 13 | 2026-09-04 | **Scope reality check from the problem statement (§7):** lock Tier 1 = 16/16 and keep it green; Tier 2 solid on S2; Tier 3 + `JOINT`/S6 are stretch. Ship the `abstain`/`confidence:low` path deliberately — it is scored, and a failure-case writeup is a deliverable. | "A polished Tier 1 with a credible Tier 2 beats a broken Tier 3."
